How this page works

  • Proposed — a suggestion waiting for your review. No file is changed.
  • Under review — you asked a professional (attorney, CPA, broker, appraiser) to respond.
  • Approved — you said to build it; the next site build includes it and this table marks it “Built”.
  • Built — the suggestion is live on the site; the row stays for history.
  • Not approved / Deferred — you chose not to build it now; the reason is logged.

Every suggestion maps to a flag on the Flagged for Review page. How to approve and what happens next

  1. Read the Flagged for Review page and the Questions to answer checklist.
  2. Tell the builder which numbered suggestions to build (e.g., “Approve S-01, S-03 to S-06, and Path 2”). No code runs until you do.
  3. The builder edits only the files listed in COORDINATION.md for the approved scope, rebuilds with final/model.py and final/build.py, and must pass final/check.py (every row has an official link, every dollar is rounded to $10, no personal information) before opening a pull request.
  4. You review the pull request — each new table row still carries its official link for manual checking — and merge only when satisfied. Flagged items never block a merge; they are published as “under review” until resolved.

If you prefer no public repository at all, choose S-18: the analysis is delivered as a private PDF and the public site keeps only the method and no household figures. That does not rewrite Git history — that history stays public until the repository itself is made private or its history is rewritten, which only you can authorize flag P02.

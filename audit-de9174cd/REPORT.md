# Independent release-safety audit

Audit date: 2026-11-11 UTC. Scope: the existing root GitHub Pages release and its public repository, at base commit `0e207a617fa5a031ccd17611c0f74c35365ca58a`. This report intentionally does not repeat private household figures.

## Release blockers requiring integration-owner action

1. **Public household financial information.** The repo is public and Pages is configured to publish the root of `main`. `index.html`, `costs.html`, and other current pages expose user-supplied financial and housing details tied together with specific locations, ownership, occupancy, and timing. The `archive/`, `dashboard/`, `docs/`, `site/`, `data/`, and `final/` trees include additional original, rounded, or derived household details. Some pages are linked through `versions.html`; even unlinked files can be retrieved by URL. Replacing names with placeholders and rounding to $10 does not make this combination non-personal or non-traceable. A `noindex` directive is not access control. Do not publish or merge a further release as privacy-safe until the entire published tree and public repository are handled, including archived material and generated data. Review Git history and prior deployments as well; deleting files from a new commit does not erase existing history or copies. Coordinate repository visibility, Pages exposure, and history remediation with the owner and platform as appropriate; a public repository and public Pages cannot host a confidential personalized analysis.
2. **Source links do not establish verification.** For example, the current landing page's comparison table associates reported private estimates and rent with county tax or rent-regulation links. Those sources do not verify the specific household values. The user required unconfirmable values to be blank and flagged, not filled in or presented as verified. Calculated forecasts and private input assumptions cannot be independently verified as official facts merely by linking an official methodology or index. A per-cell provenance review is necessary before claiming compliance.
3. **Automated pass is not a privacy or source-verification proof.** `python3 final/check.py .` passes for the root pages, but its fingerprint check only rejects selected *unrounded* tokens and the page loop scans root HTML, not recursively all published paths. The row test checks for the presence of an official-domain link, not whether that link supports each fact. It also accepts results of assumptions as long as their rows contain such links. `python3 legacy95/check_legacy.py` explicitly accepts rows with labels in lieu of official sources, contrary to the stricter user instruction. These tools cannot establish line-by-line verification or de-identification.
4. **Decisive recommendation is not established by official verification.** The landing page calls one strategy the best financial outcome based on modeling. Future returns, housing prices, costs, occupancy, applicable laws and household tax details are uncertain; results depend on assumptions. A clear recommendation should be explicitly conditional, not a verified forecast. Insurance premiums require property-specific quotes; official state guidance says its comparison tool is not an actual premium quote: [California Department of Insurance](https://www.insurance.ca.gov/0400-news/0100-press-releases/2018/release138-18.cfm).

## Verified legal reference points, not household findings

- For deaths in 2026 and 2027, respectively, the IRS states basic federal estate exclusions of $15,000,000 and $15,480,000. This is an estate-level exclusion, not a blanket amount each beneficiary can receive tax-free; adjusted taxable gifts, elections, deductions, and other facts may matter. [IRS announcement](https://www.irs.gov/newsroom/irs-releases-tax-inflation-adjustments-for-tax-year-2027-taxpayers-continue-to-benefit-from-the-working-families-tax-cuts); [Form 706 instructions](https://www.irs.gov/instructions/i706). The existing estate page already shows the 2027 figure. Future thresholds are projections, not enacted numbers.
- The California Board of Equalization describes the intergenerational family-home exclusion, including transferor occupancy, transferee occupancy, claim timing and the adjusted value limit. Eligibility and consequences depend on actual facts and law at transfer; the projected inheritance date is not confirmation of eligibility. [BOE publication 800-1](https://www.boe.ca.gov/pdf/pub800-1.pdf).

## Checks actually performed

- Read the coordination board, inspected the published root landing and costs pages, archived material, the checker, and repository/Pages configuration via GitHub API.
- `final/check.py .`: passed its own stated automated checks (21 root pages and 668 source-link-bearing table rows). This does not resolve the blockers above.
- `legacy95/check_legacy.py`: passed its own link-or-label rule for legacy tables, which is weaker than the user's row rule.
- GitHub Pages latest build reported `built` for the base commit; this establishes build status only, not privacy, factual accuracy, or a successful browser-level live review.
- Not a line-by-line verification of the entire repository, and no independent check of all external links or current legislation was completed. Do not represent this audit as full verification.

## Integration request

The release owner should design a public-only, generic, non-identifying edition with placeholders and blanks for all non-official household figures, and move personalized calculations to an appropriately protected environment. A complete cleanup must address every publicly reachable legacy page, data file, generated artifact, source code input, and the public Git history; do not rely on robots metadata. Re-audit actual claim-to-source support, update model uncertainty and flags, and verify the new deployment before claiming success. These files are outside this audit's claimed scope, so they were not changed here.
